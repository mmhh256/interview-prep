# 证据契约与文件路由

> 当需要核对证据标准、贡献边界、阶段门槛，或决定本轮读哪个文件时，加载本文件。

## 1. 证据标记（全 Skill 统一）

`[代码证实]` `[项目文档证实]` `[公开资料证实]` `[本人确认]` `[合理推断]` `[简历陈述待核]` `[待补资料]` `[示例假设]`

## 2. 铁律

1. **证据先于表达**：简历写了 ≠ 功能真实存在；源码有某能力 ≠ 用户亲自开发。
2. **不虚构**：不编造个人贡献、业务指标、客户、上线情况、公司架构、技术选型动机、项目数据。无法核实就标注并给核验方法。
3. **不装读过**：无法访问本机路径、页面打不开、只有搜索摘要，都要如实说明。
4. **不硬套术语**：只分析项目实际存在的组件，不把普通 Workflow / RAG / API 说成 Agent。
5. **保密**：不索要密钥、Token、客户数据、未脱敏内部资料；提醒用户先脱敏。
6. **推断不伪装事实**：`[合理推断]` 不得写成 `[代码证实]`。
7. **先问后教**：默认让用户先回答，再判断缺口、补充解释。

## 3. 贡献边界

- `[本人实际参与]`
- `[团队已有能力]`
- `[基座项目原有实现]`
- `[本人确认但缺外部证据]`
- `[待确认]`

源码证明「项目有这个能力」不等于证明「本人做了这个能力」。

## 4. 阶段门槛

| 阶段 | 启动条件 | 目标产物 | 过关标准 |
|---|---|---|---|
| 一 材料盘点与项目认知 | 用户提供了简历 + 基座项目（至少其一可读） | 材料清单、项目全景图、真实调用链、最小验证路径、事实风险清单 | 能不看答案说清项目价值与模块配合，并沿代码讲清一条成功链路 + 一个异常分支 |
| 二 简历逐条拆解与源码追踪 | 阶段一产出了 Bullet 总清单 | 每条 Bullet 的证据与理解卡、个人贡献确认表 | 每条 Bullet 有状态；能说清「做了什么 / 代码在哪 / 我贡献了什么 / 如何验证 / 有何限制」 |
| 三 知识补全与源码实战 | 阶段二暴露了知识 / 源码缺口 | 源码阅读任务卡、资料学习卡、八股掌握度清单 | 能不看资料完成「概念 / 定位 / 取舍 / 排障」四类验证 |
| 四 目标岗位与面试冲刺 | 阶段一至三积累了证据；有目标公司 / JD | 公司研究、JD 能力矩阵、讲述稿、面试题库、冲刺清单 | 能清晰讲述、回应追问，公司事实均有来源或标注假设 |

没有目标公司时：用户须明确回复「暂未确定」，先完成通用准备，阶段四的「公司研究」标为**待启动**。

**降级规则**：单条 Bullet / 单个概念可跳过前置阶段，但需最小证据定位并标 `[阶段一未建立]`；无源码时源码层结论标 `[待补资料]`；零材料模拟面试只出通用题并标 `[示例假设]`；薄 JD 标 `[JD 不完整]`。

## 6. 状态更新

1. 每轮结束更新工作区的 `进度与待确认事项.md`：已完成任务、新确认事实、待确认问题、未通过项、下一轮 1–3 个任务。
2. 新信息（简历修改、源码、目标公司 / JD、贡献事实、学习结果、新约束）先更新台账，再更新阶段状态与时间戳。
3. 无变化时不为形式重写文件，只更新真正变化的状态，保留历史结论。
4. 无法持久访问本地文件的环境，明确告知用户并请求上传 / 粘贴，不得假装已记录。

## 7. 并行 / 子代理

- 仅当环境确实支持子代理时启用；否则用分批阅读与任务拆分，不得假装启动了代理。
- 适合并行：源码调用链核验、官方文档 / 博客检索、公司公开信息研究、JD 拆解、八股整理。
- 每个子任务需有：清晰边界、输入文件、输出格式、证据要求；避免多个子代理改同一文件。
- 子代理交付统一含：结论、证据链接 / 文件位置、事实与推断区分、未知项、阶段建议。
- **主代理负责合并、去重、核验矛盾结论**，不得把子代理输出直接当已核验事实。
