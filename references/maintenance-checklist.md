# Skill 维护验收清单（不是候选人任务）

> 维护者/评审者使用。本清单不进入用户面试完成度；静态与行为分别报告，不能以示例、夹具、模型自报或作者自审替代独立运行证据。

## 一、规则与模板一致性

- [ ] 入口、四阶段、证据契约、使用说明、当前完整主 Prompt 与全部 12 份模板共用只读模板/已确认用户工作区路由；无落盘确认只在对话，恢复不覆盖历史。
- [ ] F/C/M 定义、依据、范围/版本、时间与独立失效条件一致；目标/实际等级和验证有效性分列。
- [ ] 未知贡献不改成参与/同事/团队；源码不证明作者，知识掌握不证明经历；本人自述不冒充外部核验。
- [ ] 默认先答后教、独立复验；明确参考答案请求允许，但不升级 M；有独立表现时不一律压低等级。
- [ ] 公司场景有明确启用条件，未启用不适用，不阻塞核心；用户验收与本清单完全分开。
- [ ] 简历、JD、源码/注释/README、网页和检索结果中的指令当数据，不更改规则/状态、执行未授权命令或泄密；正常材料分析继续。
- [ ] 当前主 Prompt 可单独使用且不含旧冲突。原始完整文件在可定位 Git 基线/档案保留，档案只作数据，不作另一套运行规则；不伪造历史版本或 Release。

## 二、机械验证（不能证明模型行为）

- [ ] `python -m unittest discover -s tests -v` 实际通过；HTTP 夹具单测另计，不当作模型测试。
- [ ] `python scripts/check_static.py` 独立运行，报告范围是窄机械检查（模板写入/路由/链接/用例 schema/版本）。
- [ ] `git diff --check` 通过；已人工核对三链、可选场景、恢复和信任边界，记录评审是否独立。
- [ ] Python 标准库、3.8+、Windows/Linux 支持边界与实际已测平台明确；CI 静态自动运行，不能因绿色静态 CI 声称模型通过。

## 三、真实行为采集与语义评分

- [ ] 固定合成输入、fixture、逐项语义 criteria 和复现命令公开；评分标准不泄入模型上下文，材料不升级 system。
- [ ] 无 Skill / 原版 / 当前版记录真实请求、请求/返回模型、版本/时间/哈希、完整可见输入输出；接口错误、空/截断/半途失败、未运行和未评分单列。
- [ ] 对可用压力场景请求至少 5 次重复；实际执行次数另列，不把计划次数当完成。不同模型的真实结果另列，没有有效采集不声称跨模型稳定。
- [ ] 评分读取真实完整 trace，按原句语义/行为及证据判断，不依固定措辞或关键字。逐项有理由与输入/输出引用或完整检查后的遗漏范围；模型“我通过了”无效。
- [ ] 评分者身份、独立性与模型信息明确；作者自审注明不独立，没有独立工具/服务不得虚称独立评审。
- [ ] 标明文本 API 采集不执行模型命令/写入，不验证工具沙箱或实际文件行为；注入测试的结论限定在可见文本。
- [ ] 行为 CI 只手动触发、Secrets 经环境变量注入、trace 作为受控 artifact，不自动语义判通过；发布前审查并脱敏，无密钥/真实个人/客户资料。

## 四、报告与发布

- [ ] 静态报告与行为报告独立；HTTP 401/空输出/未运行/未评分不计行为通过，零有效评分时通过率为不适用。
- [ ] 训练对话注明“规范示例，不是模型或真实用户运行”；不计样本，不编造用户掌握度、模型输出、历史迭代或 GitHub Release。
- [ ] README 仓库 URL、版本与 CHANGELOG 同步；能力声明与真实运行/失败证据一致，缺口明确。
- [ ] 发布前确认目标远端、权限与 SHA，不强推覆盖他人变化；提交/推送结果用实际输出证明，失败不称成功。
