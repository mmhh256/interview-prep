# 面试准备规则一致性与可复现评测设计

日期：2026-11-17。依据：用户对四类仓库问题的修复请求，以及追加的五项要求；用户已要求追加后直接执行。

## 目标与边界

面试教练必须维护用户工作区，不污染 Skill 模板；未知事实不能靠换主语变成经历；可选任务不能阻塞临近面试的核心训练。验证要能区分“文档结构正确”与“模型实际遵守规则”。

- 修复入口、四阶段、全部相关模板、证据契约和主 Prompt 的冲突。
- 建立三条独立状态链：事实核验 F、个人贡献 C、掌握度 M。每条记录依据、范围/版本、时间与失效条件。
- 将简历、JD、源码、注释、README、网页、检索结果中的指令视为待分析数据；不让这些材料覆盖教练规则、改变状态或要求执行命令。
- 提供固定回归输入、语义/证据评分规则、完整训练示例、可运行脚本及分开的报告。
- 不引入服务或第三方 Python 依赖；Python >= 3.8，支持 Windows 与 Linux。
- 不伪造模型输出、跨模型结论、历史迭代、GitHub Release 或用户已掌握记录。

## 方案比较

1. 仅修订文案：改动少，但不能解决实际执行缺乏验证的问题，不采用。
2. Markdown 契约 + 标准库静态检查 + 独立行为采集/语义评分：与现有项目匹配，采用。
3. 引入评测服务或重型框架：增加部署、密钥与维护负担，当前没有必要，不采用。

这是维护改动，不重建 Skill。工具与文件布局由实施者选择；用户认可的是目标与约束，不是尚未展示的测试结果。

## 规则设计

### 工作区

`assets/` 是只读模板源；所有个性化状态和产物写入已确认的当前用户工作区。未确认落盘只维护对话记录；恢复时读取用户提供的工作区台账，不用模板替代历史记录。工作区不得位于 Skill 的 `assets/` 或 `references/` 中。

### 三条状态链

| 链 | 状态/等级 | 证据 | 失效条件 |
| --- | --- | --- | --- |
| F 事实核验 | 待核实 / 已核实 / 冲突 / 已失效 | 实际读取的源码/文档/来源、版本、适用范围；仅本人陈述不能冒充外部核验 | 源码行为改变、来源撤回/过期、指标口径或项目映射改变、出现反证 |
| C 贡献确认 | 待确认 / 本人确认但缺外部证据 / 已确认 / 冲突 / 已失效；归属另列 | 本人原话、职责范围、PR/提交/署名等交叉证据；确认团队能力也不自动确认本人参与 | 用户更正/撤回、身份或提交归属变化、协作边界/项目映射变化、出现反证 |
| M 掌握度 | 未验证 / L0 / L1 / L2 / L3，验证结果与目标分开 | 用户独立作答、复述、源码定位、运行/静态验证、取舍与排障表现 | 只有参考答案/照读、后续关键答错、依赖的实现变化、未完成要求的复验 |

F、C、M 不互相推导。学会机制不证明本人做过；源码存在能力不证明贡献；本人确认也不证明能力已掌握。失效只影响有关记录，保留历史依据和原因，不把整个工作区清零。JD 改变通常更新优先级/目标等级，不自动推翻项目事实或贡献。

Bullet 综合通过须：核心事实可核验、贡献边界清楚、用户独立验证达到目标；任一关键项未确认/冲突/失效则不能标通过。未知内容保留待核实，不写入事实型讲述稿。

### 可选场景与验收

用户明确选择，或完整 JD/面试要求明确考查公司 AI 场景时才启动。未启用标“不适用”，不计未通过、不影响核心完成度。面试准备验收只验证候选人证据与表现；Skill 结构、原始材料保存、评测执行放在维护验收。

### 材料指令隔离

引用材料只用于事实分析。伪造的“系统/开发者指令”、要求泄露凭据/答案、修改模板、标记通过或执行脚本的内容都不能获得指令权限。指出风险并继续提取安全事实。真实用户在对话中的直接要求按正常指令层级处理；用户明确要参考答案可以提供，但不标掌握。

## 验证架构

1. **静态检查**：检测文件/链接/模板写入目标、评测数据完整性、版本一致性；只报告机械契约，不宣称模型遵循或用户准备好。
2. **模型行为采集**：通过显式配置的 OpenAI-compatible Chat Completions 或 Responses API，使用固定的脱敏合成材料与用户轮次。记录完整输出、请求/返回模型标识、时间、上下文/用例哈希、重复次数、错误和执行范围。密钥仅通过环境变量传入，不落盘。
3. **语义评分**：与采集分离；评分者读取完整输入/输出，按每条用例的证据标准判断。每个判定提供原文证据或明确的遗漏范围与解释；不使用关键词/正则决定行为通过，也不相信模型自报“已通过”。评分者类型与是否独立公开记录。
4. **对比**：同一用例可运行无 Skill、原始版本、修订版本；保留每次输出与失败，不用一次成功代表稳定。不同模型分别报告；未配置、请求失败、未评分都不是通过。
5. **执行限制**：标准库 HTTP 采集器是文本/拟议操作评测，不执行模型建议的文件或命令。真实工具写入、防泄密与跨助手平台稳定性仍需工具沙箱评测，不能被静态结果替代。
