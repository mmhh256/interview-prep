# interview-prep

**简历 × 项目源码 × 目标岗位：面向 AI 应用 / Agent 岗位的面试准备 Skill。**

从简历中的每一条经历出发，沿真实代码追踪业务流程与实现原理，核对个人贡献和指标，再通过提问、补课、复述与模拟面试，把项目理解转化为能够经得起追问的表达。

当前 Skill 版本：**1.0.2**。入口文件：[SKILL.md](SKILL.md)。

## 适合什么场景

- 有简历和项目仓库，希望逐条核验经历、梳理调用链并准备追问。
- 正在学习开源或参考项目，希望理解业务、模块协作、设计取舍与异常处理。
- 有目标公司和 JD，希望把项目证据映射到岗位能力，准备讲述稿与模拟面试。
- 面试时间有限，需要根据已经暴露的缺口安排优先级。

主要围绕具体项目展开；单纯简历润色、脱离项目的通用八股问答，以及无关的编码任务不属于主要使用范围。

## 核心方法

```text
简历与项目材料
    ↓
业务流程 → 真实调用链 → 技术原理与取舍 → 个人贡献与结果证据
    ↓
用户先回答 → 识别缺口 → 定向补充 → 不看答案复述 → 记录进度
    ↓
JD 能力映射、项目讲述与模拟面试
```

**证据先于表达。** 简历中的陈述需要核验；项目存在某项能力，也不能直接证明使用者亲自实现了它。Skill 会区分代码证据、文档证据、本人确认、合理推断和待补资料。

**每轮聚焦 1–3 个任务。** 默认先让使用者作答，再补薄弱点，并沿“为什么、怎么实现、为什么不选其他方案、出错怎么办”继续追问。拿到参考答案与真正掌握分别记录。

## 四阶段流程

| 阶段 | 主要工作 | 预期产物与验收 |
| --- | --- | --- |
| 1. 材料盘点与项目认知 | 检查材料可读性，梳理业务、模块、成功链路与异常分支 | 材料清单、项目全景图、事实边界；能沿代码讲清一条成功链路和一个失败分支 |
| 2. 简历拆解与源码追踪 | 给每条简历要点（Bullet）编号，核验实现、指标和个人贡献，执行技术九问与业务五问 | Bullet 证据与理解卡、贡献确认表；说清做了什么、代码在哪、如何验证及其限制 |
| 3. 知识补全与源码实战 | 根据缺口安排源码阅读、资料学习和动手验证 | 阅读任务卡、学习卡、掌握度清单；验证解释、定位、比较与异常分析能力 |
| 4. 岗位匹配与面试冲刺 | 研究公司与 JD，准备不同长度的项目故事，开展模拟追问 | 公司研究、JD 矩阵、30 秒 / 2 分钟 / 5 分钟讲述稿、题库和冲刺清单 |

支持全流程、单阶段、项目深挖和模拟面试。可以跳阶段，但缺失的前置证据仍须补齐；阶段完成以实际验收为准。

## 安装与加载

这是由 Markdown 指令、参考资料和模板组成的 Skill，无需安装项目依赖，也没有需要启动的服务。运行时需要能够读取这些文件的 AI 编程助手；联网检索是可选能力。

### 获取文件

```sh
git clone https://github.com/mmhh256/interview-prep.git
```

也可以通过仓库页面的 **Code → Download ZIP** 下载后解压。私有仓库需要使用有访问权限的 GitHub 账号。

### 在支持 Skills 的助手中加载

将整个 `interview-prep` 文件夹放到所用助手支持的 Skill 目录中，使文件结构保持为：

```text
<Skill 目录>/interview-prep/SKILL.md
<Skill 目录>/interview-prep/references/...
<Skill 目录>/interview-prep/assets/...
```

具体目录和加载方式以该助手的说明为准。不要只复制 `SKILL.md`，入口会按需引用其余文件。加载后，可在对话中明确要求使用 `interview-prep`。

### 手动读取

如果助手能够访问本地文件，也可以直接指定入口：

```text
请读取 <仓库绝对路径>/SKILL.md，并使用 interview-prep 帮我准备面试。
按需读取引用文件，先盘点我提供的材料，再开始本轮任务。
```

无法自动加载 Skill 时，这种方式仍要求助手具备文件读取能力。仅粘贴入口内容，不能替代对参考文件和模板的读取。

## 快速开始

建议准备以下信息；暂缺的内容可以明确写“暂未确定”：

| 材料 | 需要提供什么 |
| --- | --- |
| 简历 | 完整简历，或本轮需要拆解的全部经历原文 |
| 项目 | 可访问的仓库、脱敏源码或 ZIP，并说明与简历项目的关系 |
| 目标岗位 | 公司、职位、职级、面试轮次及 JD |
| 真实经历 | 实际负责、修改、设计或排查的部分，以及团队或参考项目已有的能力 |
| 时间与约束 | 面试时间、每天可投入时间、技术基础及是否允许联网 |

### 从零开始

```text
使用 interview-prep 帮我准备 AI 应用 / Agent 岗位面试。

简历：<文件路径或原文>
项目：<仓库地址或本地路径>
目标公司与 JD：<内容，或暂未确定>
本人实际负责：<真实工作范围>
面试时间与每天可投入时间：<时间安排>
是否允许联网：<是 / 否>

先检查材料是否可读，合并追问关键缺失信息。
从项目认知开始，每轮只安排 1–3 个任务，先让我回答再补充。
```

### 只拆一条简历要点

```text
使用 interview-prep，只拆解下面这一条经历：
<Bullet 原文>

相关源码：<路径>
我的实际贡献：<说明>

先核对代码、贡献和指标证据，再让我讲清实现过程并追问。
```

### 只读项目，暂时没有简历

```text
使用 interview-prep，带我吃透这个仓库：<路径或地址>。
我暂时没有对应简历，先梳理业务、模块、成功调用链与异常分支，
再安排源码阅读任务。请将项目能力与本人贡献分开标记。
```

### 模拟面试

```text
使用 interview-prep，根据以下已核验经历和 JD 进行项目 / 技术模拟面试：
已核验 Bullet 与证据：<内容或文件路径>
JD：<内容>

每轮先问一个问题，等我回答后追问 2–3 层，记录未通过项。
```

## 进度保存与恢复

Skill 会先确认是否将学习资料保存到本地。确认后，以 `assets/` 中的模板建立工作区，并使用 `进度与待确认事项.md` 记录阶段、已确认事实、待确认问题、掌握度和下一轮任务。

在新对话中，可以这样继续：

```text
继续面试准备。Skill 路径：<路径>；工作区路径：<路径>。
先读取 references/evidence-contract.md 和工作区的进度与待确认事项.md，
说明当前阶段、已确认事实、未通过项和下一步，只读取本轮需要的文件。
```

没有保存工作区时，进度保留在对话中；跨对话需要提供之前的台账或记录。文件不可访问时，助手应明确说明。

## 证据与贡献边界

| 标记 | 含义 |
| --- | --- |
| `[代码证实]` | 能在源码中直接定位实现 |
| `[项目文档证实]` | 项目 README 或设计文档中有说明 |
| `[公开资料证实]` | 有可核验的公开资料支持 |
| `[本人确认]` | 使用者明确说明，未必有外部证据 |
| `[合理推断]` | 基于已有证据的推断，需要与事实区分 |
| `[简历陈述待核]` | 简历中的说法尚未核实 |
| `[待补资料]` | 当前材料不足以判断 |
| `[示例假设]` | 仅用于演示的假设 |

贡献还会单独区分本人实际参与、团队已有能力、基座项目原有实现和待确认内容。涉及效果数字时，需要核对口径、样本、基线、计算方式与证据，不能自行补造。

## 使用边界

只提供简历时，可以做表述核对与知识练习，源码结论保持待确认；只提供仓库时，可以做项目认知与源码学习，但不能把仓库能力认定为本人贡献。缺少完整 JD 时，岗位映射与优先级结论也应保留相应限制。

不要提供密钥、Token、客户数据或未脱敏内部材料。公司事实需要有来源，无法读取的文件不能视为已经核验。Skill 提供准备流程与模板，实际效果仍取决于可读材料、助手能力及使用者的回答和验证。
